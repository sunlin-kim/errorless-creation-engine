# 오프라인(비행기모드) 실기기 검증 체크리스트

비수탁 지갑의 핵심 안전 속성은 **네트워크 없이도 시드 해독·주소 파생·서명 준비
가 동작**해야 한다는 점이다. 송금 방송(RPC) 만 네트워크가 필요하다. 아래 단계를
실기기에서 그대로 따라 검증한다.

## 사전 준비
1. `bun run cap:sync` 로 APK 산출물 빌드 + Android 프로젝트 동기화.
2. Android Studio 에서 release/debug APK 빌드 → 실기기 설치.
3. 앱 최초 1회만 인터넷 ON 상태로 실행해 시드 생성·잠금 비밀번호 설정.
4. 시드 백업 12 단어를 안전한 곳에 종이 백업.

## 비행기모드 검증
| # | 동작 | 기대 결과 |
|---|------|-----------|
| 1 | 비행기모드 ON (WiFi/모바일 모두 OFF) 후 앱 강제 종료 → 재실행 | 스플래시 → `/wallet/unlock` 셸 정상 렌더 (RPC 호출 실패 토스트는 정상) |
| 2 | 비밀번호 입력 → 잠금 해제 | `/wallet` 셸 렌더, 주소 5종(BTC/ETH/BNB/SOL + USDT) 표시 |
| 3 | "보내기" 진입 → 자산 선택 → 받는 주소 입력 → 비밀번호 재인증 | 비밀번호 모달 통과까지 정상. **방송 단계에서만** "네트워크 오류" |
| 4 | "받기" → QR 코드 렌더링 | QR 이미지 정상 표시 (qrcode 는 클라이언트 라이브러리) |
| 5 | 자동 잠금 10분 경과 또는 백그라운드 전환 후 복귀 | 자동 잠금 발동 → 다시 비밀번호 요구 |
| 6 | 화면 캡처 시도 | Android `FLAG_SECURE` 로 캡처 차단 / 최근 앱 썸네일 블랙 |

## 실패 시 점검
- 1번 실패(빈 화면) → `capacitor-web/index.html` 이 placeholder 인지 확인.
  실제 SPA 산출물로 교체되어야 하며, `bun run build:capacitor` 의 자가 검증이
  통과해야 한다.
- 2번에서 주소가 안 보임 → 시드 해독은 됐지만 잔액 RPC 가 실패한 정상 상태.
  주소 자체는 표시되어야 한다 (`derive.ts` 는 오프라인 동작).
- 3번에서 비밀번호 모달이 안 뜸 → `wallet.send.tsx` 의 재인증 모달 회귀.

## 자동화 스모크 (선택)
빌드 산출물을 정적 서버로 띄운 뒤 네트워크를 끊고 셸 렌더만 확인:
```bash
bun run build:capacitor
npx serve capacitor-web -l 4173 &
# 다른 셸에서 (네트워크는 RPC 도메인만 차단해도 충분)
curl -fsS http://localhost:4173/ > /dev/null && echo OK
```
RPC 도메인을 hosts 파일로 막아두면 잔액 fetch 실패만 발생하고 셸은 살아 있어야
한다.
